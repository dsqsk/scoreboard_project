# 最近房间开发任务

2026-10-22，用户已授权优先完成此功能。业务依据PRD HR01—HR06，视觉及手势依据docs/design/home-recent-handoff/SPEC.md。

## 目标与边界

首页最多3个本人最近房间，按主动进入时间倒序、同房去重。左滑显露删除，一次仅展开一条；横滑不导航，纵向滚动正常，点击展开主体仅收起。删除中保留卡片并防重；成功后补位，失败保留并重试，空态“暂无最近房间”。现有“全部”入口保留，展示未隐藏条目，不受首页3条限制。

移除只改变本人最近条目的可见性，持久化到云端；不退出房间、不变更成员资格、不删除房间、牌、记录或累计，不影响其他人。普通快照、轮询、重连和后台更新不得恢复隐藏项，也不得重排最近进入顺序。创建、码/分享加入及主动点击进入可恢复并更新排序。身份来自可信上下文，不能传其他userId操作。

## 技术契约与所有权

- 后端维护apps/cloud及packages/shared，先冻结并同步契约，再实现。建议room.dismissRecent和room.enter两个写action，均requestId+roomId；最终命名由后端确认并写入交付。客户端RoomApi对应dismissRecentRoom和enterRoom，返回既有收据类型。room.join对已加入用户仍属于主动进入，恢复条目；原请求重试仅返回旧回执，不重复更新进入时间。
- getSnapshot改为只读访问语义，不隐式更新lastVisitedAt。房间首次打开时前端显式发一次enterRoom；刷新不重复调用。create/join后再enter允许，但不得由每次快照触发。
- 列表过滤隐藏条目后取足够数据补位；不得固定扫描20条后直接过滤导致空缺。后端确定稳定分页契约并同步前端；旧无隐藏字段的成员关系仍可见。索引、权限或迁移需求写入交付。
- 前端维护apps/miniapp；消费shared，不与后端同时改共享文件。负责首页/全部列表、手势组件、移除状态、Mock持久化、cloud映射及主动进入接入。
- 超时可能已提交，原ID同载荷恢复；待确认操作按用户/环境隔离持久化，不能换ID重发，也不能新请求覆盖待确认操作。防止迟到列表响应复活已移除条目。
- 两端可就已授权任务互相同步接口及联调问题，完成后分别在各自交付文档报告。本轮不扩展其他玩法、资料或房间生命周期。

## 验收与交付

覆盖HR01—HR06，以及：隐藏超过20条仍正确补位；普通刷新不复活/不改排序；已隐藏房间主动直达恢复；他人列表和成员权限不变；重复请求、未知结果恢复、跨身份隔离；现有创建/加入/打分无回归。

前端提供有意义的状态与交互测试、类型检查、微信构建、DOM状态走查截图；有条件进行微信手势验证。后端提供权限/幂等/持久化/查询补位测试及部署包检查。技术总监执行集成检查并核对交付证据。源码、构建、部署、真实微信/多账号验收分别标注，不相互替代。允许部署本任务所需api和必要索引/字段兼容调整；不得破坏或清空既有数据。

## 本轮结果

前后端开发完成，api已部署。最终契约为room.enter、room.dismissRecent、room.listRecentPage，保留旧room.listRecent兼容入口；shared由后端维护。仅新增可选recentHidden并复用现有索引，无需迁移。

前端61项测试及微信cloud构建通过，后端42项测试及部署包检查通过。技术总监独立全仓typecheck通过，核对了核心代码、DOM手势状态及微信恢复截图。微信开发者工具真实云端单用户已验证左滑移除、重新编译仍隐藏、原房间码重入恢复且无重复成员；DOM验证首页3条/全部列表/补位/失败/未知恢复。

实体手机手势及真实双账号隔离未验收；超过20条隐藏的补位由本地测试覆盖，不能外推为线上大列表验收。详情和证据见docs/development/RECENT-ROOMS-FRONTEND.md与RECENT-ROOMS-BACKEND.md。
