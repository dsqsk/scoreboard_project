## 数据与环境

默认使用独立Mock Adapter，页面始终标注本地演示。其数据持久化到当前设备的`scoreboard.mock.v1`，不会写入真实后端。初次最近房间为空；演示码628391对应小林、小周的杀球房间，加入后本人为第三人。

运行前端：根目录`npm run dev`；导入根目录project.config.json至微信开发者工具。Mock不依赖真实云环境。

云接口Adapter按仓库当前foundationRequestSchema发送动作，DTO在Adapter中转换为前端ViewModel，不覆盖共享后端契约。显式配置`TARO_APP_BACKEND=cloud`及`TARO_APP_CLOUD_ENV`后才走云调用，云调用失败不回退Mock。无效BACKEND值会令构建失败。

## DOM走查工具（不作为H5产品）

根目录运行`npm run preview:dom --workspace @scoreboard/miniapp`，访问http://127.0.0.1:8766。只绑定127.0.0.1；可带`?width=320`检查窄屏。

此工具将实际React页面源码映射到简化DOM组件，独立于小程序构建、微信SDK与真实后端。预览顶部标明非微信运行时；不能用于证明微信组件兼容。脚本中的分享仅提示需要微信验证，不模拟分享成功。

页面底部“开发走查工具”可让下一次Mock请求失败或让下一次写入丢失响应，检查错误/恢复流程。工具仅存在于DOM harness，不打包到微信小程序。

`.preview`为忽略的生成目录。停止预览服务即可关闭本地端口。

## V4样式修正补充

- 在微信开发者工具实际复现首页模式按钮宽度不一、文字黑色。只读selector探针初始返回pass=false，宽度约46/24/28.32/31.48/35px，color均为rgb(0, 0, 0)。
- 根因：Taro将源文件的button类型选择器改写为.h5-button，原生Button未命中原先的全局重置；模式按钮也没有明确宽度及文字色。早期DOM走查没有模拟该平台差异。
- 统一使用BaseButton附加ui-button class实施重置；模式入口显式100%网格宽、min-width:0、border-box、零外边距，标签与图标使用V4文字色。修复同时覆盖模式选择弹窗等按钮。
- 同一原生探针复测pass=true，五个宽度约73.59—73.60px，color均为rgb(244, 245, 241)。这是微信模拟器实测，不是仅DOM预览。
- 首页模式图标、11px标签/23px标记、7px列间距、70px最小高度、创建按钮居中与Hero间距按V4校正；Hero使用交付包原始1号/5号SVG，已在模拟器确认显示。移除设计稿中没有的页脚；最近房间“全部”入口显示实际房间列表，不填充虚构历史。
- ScrollView底部安全区padding移至内部View，避免原生scroll-view不支持padding造成内容偏差。
- 保留scripts/check-home.wx.js作为开发者工具只读回归探针，不会打包进小程序，不写应用状态。11项现有测试、前端类型检查和最终微信构建通过。
