# 默认个人资料前端交付

2026-10-22。取代首次强制填写昵称和选择头像流程，后端已同步部署。

## 行为与边界

- 首次微信身份识别由后端从固定词库生成“形容词+的+动物”昵称及person-v1小人颜色，保存一次。展示昵称允许重复；内部userId仍是唯一身份。
- 首页、房间分享、房间直达、扑克创建直接继续原流程，不因资料填写拦截。身份请求失败仍展示可重试状态，不伪造服务端身份。
- 默认头像由公共SVG模板本地绘制，颜色仅接受六位十六进制RGB，模板有白名单。颜色由共享生成器限制亮度，前端渲染不随机。默认图片无需上传云存储。
- 已有上传头像优先展示；没有上传头像时显示默认小人。个人入口、资料预览和房间成员列表使用同一Avatar组件；图片加载失败显示昵称首字作为兜底。
- 保留自选头像和昵称编辑入口。只改昵称时省略avatarFileId，沿用原默认或上传头像；选择微信头像后自动聚焦nickname输入框，需用户分别确认。
- 旧的结果未知资料请求仍按环境及userId隔离恢复，保留原ID、原载荷，不重复上传。上传/保存失败不虚构成功；旧活动快照不重写。
- Mock使用shared同一词库和生成器，初次生成后持久化。旧Mock资料补齐默认头像，保留已有自选资料。
- 原生云调用统一使用按环境缓存的独立wx.cloud.Cloud实例，等待初始化完成；保留方法receiver，初始化失败允许重试。对应后端发现的默认实例empty poll result问题。

## 验证

- 前端50项测试通过，覆盖默认资料持久化、直接创建、只改昵称不上传、SVG颜色注入防护、原请求恢复与上传失败。
- 微信动态Function兼容性回归及独立Cloud初始化/receiver/失败恢复检查通过。
- 前端类型检查、云模式构建通过。
- DOM走查：分享房间628388直接进入确认页，默认昵称“元气的企鹅”及紫色小人正常显示；不上传头像保存资料后仍返回同一分享路径。
- 微信开发者工具云模式实际显示“自在的狗”及绿色小人，与后端分配颜色#45CB57一致，无首次填写拦截。后端连续getMe读取稳定；未替用户修改正式昵称或选择正式头像。
- 本轮未在实体手机重新验收原生chooseAvatar和昵称键盘快捷填写；该可选入口保留原流程。
