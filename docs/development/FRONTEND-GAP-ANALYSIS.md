# 当前前端功能缺口核对（不含九球）

核对日期：2026-10-21。依据当前 PRD、UI-UX、扑克最终交付及其后用户样式调整，对照当前源码；本次为静态分析，不修改业务实现，不把 Mock 流程或既往构建成功当作云端业务验收。

## 结论

已具备房间创建/加入壳、三人杀球本地流程、两种扑克个人记分本地流程。新增最近房间规则尚未实现；打分原为占位页，现已按第四步补齐三人版；同房间切换玩法、固定活动名单、跨设备共享与综合记录/累计尚未形成完整闭环。

## 最近房间：新增需求与实现差异

需求来源：PRD「首页最近房间」HR01—HR06、UI-UX 同名小节。

| 项目 | 当前实现 | 缺口/验收 |
| --- | --- | --- |
| 首页最多3条 | 首页直接遍历全部 `recent.rooms` | 仅展示最新3条；不足按实数，不造占位；“全部”入口可继续保留，新需求没有要求删除它。 |
| 本人最近进入倒序、去重 | Mock 维护去重 recentIds；云端按 lastVisitedAt 排序 | 基础已有，加入移除后仍须保证排序、去重与补位正确。 |
| 左滑露出删除 | 无滑动状态或删除入口 | 横/纵手势区分；一次只展开一张；右滑/外点/点展开主体收起且不导航；删除命中区至少44px、与卡片同高。 |
| 只移除本人最近条目 | RoomApi/共享契约无该命令 | 增加持久化本人可见性及写接口；不得改变成员资格、解散房间或删除成绩。 |
| 删除反馈与补位 | 无移除 mutation | 提交中防重复；成功后从后续条目补足3条；失败保留卡片并允许重试；结果未知须确认原请求。 |
| 重开仍隐藏、主动重入恢复 | 无隐藏状态 | 列表刷新不能复活；码/分享重入后恢复最新位置，原成绩不变；另一用户列表不变。 |
| 空态与静态规格 | 仅原空态、原静态稿 | 推荐使用“暂无最近房间”；补齐展开、提交中、失败、删除最后一条等状态及测试。 |

代码依据：`pages/index/index.tsx` 80—88行直接展示全部条目；`modules/room-api/types.ts` 无移除方法；`packages/shared/src/contracts/foundation.ts` 仅有 room.listRecent，没有移除最近条目命令；`apps/cloud/src/repositories/wx-store.ts` 36—39行只按有效成员查询。

两个实现细节需要特别处理：

1. 最近条目的可见性必须与成员状态分开。不能通过把 room_members.status 改为非 active 来“删除”，否则会丢失入房资格，违背需求。
2. 当前 Mock 的 getRoomSnapshot 会把房间推到 recentIds 首位；云端 getSnapshot 也更新 lastVisitedAt。接入隐藏后，不能让普通后台刷新/重试把已隐藏房间重新加回。应明确区分主动进入与普通读取，或提供不会复活隐藏条目的访问规则。

补位需从未隐藏的后续条目读取足够数据，不能只把首页当前3条在前端过滤后就结束。当前云端列表固定取最近20个有效成员关系，后续“全部”与隐藏过滤的分页语义也需要补齐。

## 需要定规则、不能直接当作实现遗漏的部分

- 杀球四人谁分3张、发牌权限、重发和新一轮入口：P10。四人尚未开放，不应擅自随机指定少牌者。
- 杀球误转归如何更正、选牌时他人归属信息的范围：P09；当前进球撤销不等于转归回退。
- 打分四人及其他人数、小数精度：P03；不阻止先完成已明确的三人版本。
- 扑克自定义底分范围/精度、中途修改与生效时段：P04；预设1/5/10已可用，自定义仍禁用。
- 保存后更正/撤销权限：P05；不自动把杀球的进球撤销套用到扑克流水。
- 关闭/销毁房间、有效期、成员离开等生命周期：P06/P07。此次“最近条目移除”已经确定，不能再把它整体归到P06而停止开发。
- 昵称头像获取及分享加入访问范围：P08。

## 文档需要跟进的地方

技术设计仍保留旧版扑克全员结果表单、对家选赢家，以及“扑克无高保真稿”的说明；PRD共同需求与部分旧验收还提到计算预览。实现应继续以扑克最终SPEC及后续用户修改为准，后续统一文档口径。最近房间的静态稿也尚未补滑动状态，UI-UX已明确注明。

## 建议开发顺序

1. 最近房间：先完成首页3条上限、可复用滑动卡片、Zustand移除状态与Mock持久化，再接后端用户可见性接口；验收HR01—HR06。
2. 打分三人版已在第四步补齐，后续完成真实微信三人验收。
3. 活动与房间共用能力：固定名单、同房间切换、历史与累计；需要明确杀球下一轮规则。
4. 后端联调与微信验收可按功能并行推进；面向朋友实际使用前，云端业务和跨设备共享是必需项，不能只完成本地Mock便视为可用。
