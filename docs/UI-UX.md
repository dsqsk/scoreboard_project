# 台球与扑克记分｜UI/UX设计文档

版本：v0.1，供评审的交互设计稿  
日期：2026-10-20  
需求依据：[PRD](./PRD.md)

## 1. 设计目标与状态说明

让朋友在线下活动中用尽量少的操作完成记分，手机放下后继续比赛。房间成绩应易读，正在输入、已计算和已保存应清楚区分。

本文将PRD转化为页面和交互方案；页面布局属于本次设计提案，不代表此前已确认的UI。PRD未确定的业务边界以“待确认”标记，不能因本文绘制了页面而视为已确认。

主要目标：

- 九球进入后可直接记分，普通操作一次点击完成，不弹逐次确认框。
- 杀球随机分配初始号码牌，以自己的牌为主体，同时展示其他人的剩余数量；不自动判断犯规。
- 打分点击公共牌即记给自己，能明确看出每张牌的归属。
- 扑克计算时直接看到乘底分后的结果，只有主动保存才进入累计。
- 房间、玩法、本人和统计单位始终可辨识，切换玩法不混淆成绩。

## 2. 信息架构

```text
首页
├─ 创建房间
├─ 房间码加入
└─ 最近房间 → 房间
微信分享 → 房间加入确认 → 房间

房间（默认进入当前记分页；未选择玩法则展示玩法选择）
├─ 记分
│  ├─ 选择玩法 / 确认参与者 / 扑克确认底分
│  ├─ 中式九球：持续计分板
│  ├─ 杀球：随机发牌、我的牌与他人剩余数、结果录入
│  ├─ 打分：公共牌区
│  ├─ 打大A：五人基础分计算器
│  └─ 打对家：四人倍数计算器
├─ 记录：按玩法查看计分流水或保存结果
└─ 累计：按玩法查看当前房间个人成绩
```

“记分 / 记录 / 累计”采用房间内部导航，不作为跨房间的全局底栏。房间标题处提供返回首页入口。最近房间是恢复使用的设计提案，是否有过期或失效由PRD P06确定。

## 4. 通用界面结构

```text
┌──────────────────────────┐
│ ‹ 房间名称      房间码 分享 │
│ 中式九球 ▾       3人       │
├──────────────────────────┤
│ 记分       记录       累计 │
├──────────────────────────┤
│ 本玩法主要内容              │
│                            │
│                            │
├──────────────────────────┤
│ 主要操作区 / 保存按钮       │
└──────────────────────────┘
```

- 微信原生导航及右上胶囊占用区域按实际设备避让，房间信息置于内容区。
- 当前玩法点击后打开玩法选择面板，分“台球”和“扑克”两组，共五个入口。
- 本人按userId标“我”，昵称允许重复，头像颜色也不保证唯一。操作绑定userId，不依赖显示名；重名自动短后缀尚未实现，如需增加另行设计，不标为本轮完成。
- 固定底部操作区避开安全区和输入键盘，内容可以滚动到底，不被按钮遮挡。
- 房间当前玩法为共享状态的设计提案；切换时检查未保存输入或未完成公共牌，不静默丢弃或清零。并发切换冲突提示“房间玩法已更新，请确认后继续”。
- 房间成员与当前活动参与名单分开展示，但不使用“旁观者”称谓。尚未参加当前活动的人提示“下一次参与”，不能修改当前活动记录。

## 5. 创建、加入与准备

### 5.1 创建

首页点击“创建房间”→先选择游戏模式（扑克还需确认底分）→确认创建→进入对应模式房间，展示房间码和分享按钮。首版不要求填写房间名称、简介等非必要资料；名称可使用系统默认展示，是否可编辑后续确定。

创建成功即可邀请朋友，不要求先把完整参与名单填好。玩法人数满足后才启用对应计分功能。

### 首页最近房间：展示上限与左滑删除

- 用户要求最多显示2或3个；本稿按最多3个排版，不足时仅显示实际条目，按本人最近进入时间倒序。同房间去重，不因条目增多撑长首页。
- 卡片左滑露出右侧“删除”按钮。按钮采用删除语义颜色和明确文字，触控区域至少44×44逻辑px，按钮高度与卡片一致；正常态不常驻显示删除按钮。
- 一次只展开一张卡片；展开另一张时收起前一张。右滑、点击卡片外部或点击已展开卡片主体时收起，收起动作不进入房间；普通收起状态点击“进入房间”按正常导航执行。
- 横向滑动优先识别为操作卡片，不能误触进入房间；纵向滑动仍滚动页面。滑动距离阈值由实现调整，但展开后删除入口必须完整可点。
- 点击删除仅移除本人最近条目，默认不增加逐次确认弹窗；提交中禁用重复删除，成功移除并补下一条，提示“已从最近房间移除”。失败卡片保留，提示“移除失败，请重试”。
- 使用“删除”作为操作文字，成功提示和语义明确为列表移除；不能显示“房间已删除”，也不能解散房间或清除成绩。
- 删除状态需要持久保存。通过房间码或分享主动重新进入后，再恢复为最新条目。
- 全部移除后沿用“还没有一起记过分”空态或更中性的“暂无最近房间”，保留创建与加入入口；建议使用后者以避免暗示历史计分被清空。
- 本次仅更新需求与交互说明，既有静态首页稿需在后续修订时补齐左滑展开、删除中、删除失败和空态，不将原稿视为已覆盖这些状态。

### 5.2 加入

- 房间码：输入框支持粘贴，按钮为“查找房间”；查询成功展示加入确认，避免输错码直接进入陌生房间。
- 分享：打开后直接展示对应房间加入确认，无需再输房间码。
- 已加入成员从分享或最近房间返回时直接恢复房间，不重复创建身份或参赛记录。
- 房间不存在时提示“未找到这个房间，请检查房间码”；失效、无访问资格等结果按服务端明确原因展示，不捏造原因。
- 首次微信隐式身份识别自动获得后端持久化默认昵称与小人头像，不强制填写资料即可继续创建、加入及分享直达；默认昵称不等于微信昵称。身份失败仍需重试。

### 5.3 玩法准备

九球显示“2或3人”，杀球“3或4人”，打大A“5人”，打对家“4人”。打分“2～3人”，名单必须包含本人、唯一且来自房间；超出范围不能开始，选满3人不能继续添加。

扑克准备区必须展示底分输入和“确认底分”含义。已启用的计算器持续显示底分，不每保存一笔就重新要求输入。底分修改入口及权限待P04确认；历史详情始终显示原底分。

## 6. 中式九球交互

### 6.1 页面布局（三人示例）

```text
中式九球 · 3人
小林          小周          我
−10           −10          +20

合计 0分

我的记分
             扣分        得分
普胜         −4          +4
小金         −7          +7
大金         −10         +20
犯规         −1          +1
让杆普胜     −8          +8
让杆小金     −14         +14

最近：我 大金 +20 · 已保存
```

- 成员卡只展示成绩；本人操作区统一放在下方，避免点错其他人。
- 行名与正负数字同时出现，不能只用红绿按钮代表输赢。
- 所有快捷项直接可见，三人大金+20一次完成，不弹选人、上下家或逐局结果面板。
- 本页展示当前九球计分板合计；累计页明确标“房间九球累计”。若首版只保留一个持续板，两处数值一致，不制造“本局”字段。
- 两人布局沿用此结构；大金及让杆的未确认数值需在开发前确定，不将三人+20复制过去。

### 6.2 操作和反馈

点击按钮→该次请求显示“保存中”→成功后分数更新并显示简短“已记 +4”。等待期间该按钮不重复发出同一请求；成功后恢复可点，多次主动点击均为独立记分。

网络失败时显示“未保存，点击重试”，不让失败数值混入共享累计。重试同一次操作只保存一次。

合计非0时在成员卡下显示温和提示：“当前合计 +10分，可能还有人未记分”。允许继续操作，不弹阻断框、不自动补齐。合计回到0自动更新提示。

九球没有“开始下一局”“结束本局”“结算”按钮。关闭页面直接离开，已保存记录保留。

## 7. 杀球交互

### 7.1 页面主体

```text
杀球 · 3人
其他玩家
小林 剩5颗               小周 剩5颗

我的牌 · 剩5颗
[ 1 ]  [ 4 ]  [ 7 ]
[ 11 ] [ 15 / Joker ] [ ＋ ]

已发牌 · 初始分配已保存
[记录本次结果]
```

- 自己的牌占主要内容区域，突出球号，按号码升序排列；14、15号辅助显示Joker，不只显示难以区分的牌面。
- 其他人的卡片只需显示姓名及剩余颗数，四人时展示三张紧凑卡片；主体不展开其他人的号码。
- “剩余”刚发牌时等于初始获牌数，之后按本人已保存的进球标记更新；其他成员同步看到最新数量。
- 已确认：点击自己尚未进球的号码牌，直接标记已进，剩余数减1，无需逐次确认弹窗。
- 已进牌留在原位置，使用弱化样式及“已进”文字标记，不仅依靠颜色区分；页面主体仍显示自己的整组牌。
- 提交中显示局部保存状态并防止重复提交；保存成功后同步本人剩余数，失败保留未进状态并提示重试。已进牌再点不重复扣减。
- 重新进入恢复牌状态及剩余数。此操作只记录玩家确认的进球，不判定犯规，也不自动结算或重新发牌。
- 已进牌上方显示独立“撤销”按钮，点击后恢复未进、剩余数加1；重复点击牌面本身不触发撤销。按钮触控区至少44×44，牌格预留按钮位置，避免出现按钮时布局跳动。
- 撤销保存中禁用该牌相关操作；失败仍保留已进状态并提示重试，成功后同步其他成员。

### 7.1.1 惩罚转归选牌

- 自己牌组最后增加一张与号码牌尺寸一致的空白牌，有边框，中央为“＋”，辅助说明“添加惩罚球”。
- 点击打开选牌弹窗，展示1—15号号码选项；自己已持有的牌禁选，避免重复添加。选择其他人的牌时不自动转归，需点击弹窗“确认添加”。
- 弹窗主标题为“选择转入的球”，可选择一个号码；一球一次提交，不要求输入惩罚原因。取消或点关闭不改变牌组。
- 确认时提示所选号码将转入自己并恢复为未进。是否显示原持有人和已进状态涉及他人牌可见范围，待P09确认；不得默认展示他人整手牌。
- 成功后该牌从原玩家牌组移除，加入自己的号码排序中；自己剩余数加1，原玩家若该球未进则剩余数减1，若已进则剩余数不变。＋牌始终位于最后。
- 归属和数量一次保存、同步；失败保留原状态并提示重试。并发归属改变时提示“该球状态已变化，请重新选择”，不覆盖其他人的最新记录。
- 转归后的牌可正常标记已进并通过其上方按钮撤销进球；该撤销只恢复进球状态，不将牌还给原主人。误转归的回退方式另待确认。
- 其他人具体牌的隐藏目前是展示方案，不等于已经确认的私密权限；访问范围按P09确定。

### 7.2 随机发牌流程

确认3或4名参与者→点击“随机发牌”→显示发牌中→所有人读取同一份分配→进入个人牌主体。

- 未发牌时显示“尚未发牌”，不显示假牌或0颗剩余；提供发牌入口，具体谁可发牌待P10确认。
- 三人每人5张，四人4、4、4、3张，1—15完整且不重复；四人谁拿3张待确认。
- 发牌按钮提交中禁用；失败可重试，成功后入口替换为已发牌状态，重新进入不重新随机。
- 已发牌后不提供一键覆盖的常驻按钮。“重新发牌/下一轮”的权限、确认和历史保留待P10明确，防止误触换掉全员初始球。
- 不增加翻牌动画等必要等待，优先快速看到自己的号码。

### 7.3 最终结果录入

点击“记录本次结果”打开结果表单，采用选赢家、填其他人剩余颗数的设计提案；预览赢家正分及输家负分后主动保存。

- 输入非负整数，0与未填写有区别；支持键入和步进。
- 不按初始发牌数限制最终剩余数，惩罚可能增加个人名下球数。
- 赢家所得等于其他人剩余数之和，结果保存后更新累计。
- 当前剩余数如果已有确认的更新来源，可作为预填值；保存前允许核对，不自动判胜。
- 保存成功保留本次牌和成绩摘要，不自动重新发牌。“下一轮”流程由P10补齐。

## 8. 打分交互

### 8.1 页面结构

页面上部按本场名单展示两列或三列当前进球分，初始均为0，本人按userId标“我”；公共牌区位于屏幕中间，是页面操作主体。选牌成功后立即更新对应玩家进球分。

“当前进球分”作为主数字，已记录进度和本场基准放在辅助区；两人基准60、三人40。最终净分为进球分减本场基准，不用房间人数计算；准备、结果预览与历史卡片均显示对应基准。以下是三人示例，不限制两人布局。

公共牌区在屏幕中间使用3列×5行展示全部15张牌，使号码、归属及触控区在窄屏也清晰。常规字号和屏幕下优先让本场两家或三家分数与15张牌同时可见；小屏或大字体允许滚动，不压缩触控目标。每张牌突出号码1—15；14、15可辅助显示Joker，但号码必须保留。1—13的花色/牌面映射不影响计分，最终视觉映射后续确定。

```text
我 18分       小林8分       小周6分
当前进球分

已记录 6/15张     进球总分 32/120
三人 · 每人基准40分

[ 1 小林 ] [ 2 小周 ] [ 3 未选 ]
[ 4 我   ] [ 5 我   ] [ 6 未选 ]
...号码至15...

点未选牌，记给自己
```

### 8.2 选牌与修正

- 点未分配牌：表示操作者已打进该号码球，直接提交归本人，无需选择得分人；保存中显示局部状态，成功后显示本人标识及更新本场比分中的本人进球分。
- 多人同时选择：仅成功者得牌；另一人收到“6号已由小林记录”，页面刷新该牌，其他操作不受影响。
- 点已分配牌：打开底部面板，展示“6号 · 当前归小林 · 最近由小周修改”，提供“退回公共区”和“改归属”。
- 改归属：选择一名本场参与者并确认，此时一次提交完成扣原分、加新分；修改人写入记录。
- 退回公共区：确认后恢复未分配，并扣除原得分。不得因撤回而删除修改痕迹。

### 8.3 完成与累计

15张均有合法归属且合计120后出现完整结果预览及“保存本次结果”；未齐时按钮不可用，提示“还有3张未记录”。公共牌过程会持续保存，但只有完整结果主动保存后计入累计，避免用户把进行中分数当成最终成绩。

保存成功后展示已保存结果与“再来一次”，不自动清空牌。重新开始前重新确认包含本人的2～3人固定名单；晚加入不改变当前名单与底分。同一完整结果重复保存不得重复累计。

保存前可按上述方式修正牌。保存后的更正涉及累计冲正，属于P05待确认，不能将进行中修改入口直接用于已结算结果。

## 9. 打大A个人快捷记分板

### 9.1 创建与布局

选择打大A→确认底分1/5/10或自定义→创建，取消不生成房间；自定义范围精度待确认。房间名下一行显示房间码、人数、底分，不设独立底分面板。

上方显示五名入局玩家累计，按userId标“我”。左侧依次＋、−、本次明A×2，按钮加宽并铺满分配列；右侧八个等宽折算分值。加宽后精确列宽待P12确认，旧64px不是冻结要求。

- 基础键1/2/3/4/6/8/16/32，底分5普通显示5/10/15/20/30/40/80/160；本次明A选中显示10/20/30/40/60/80/160/320。
- 明A为本次按钮，位于−下方，不使用持续开关；再次点击可取消。只影响本人此次输入。
- 分值下方不加倍率说明，不设置独立计算式或预览区。底部仅“确认记分”和“仅更新我的分数”。
- 分值点击只选择，确认后保存本人流水，其他人不自动加减；无主A、同伙、名次或全员表单。

### 9.2 保存状态

未选分值禁用确认。保存中防重复；失败保留选择并提示，未知结果使用原ID原载荷确认。成功更新本人累计、清空分值选择、明A恢复普通，底分保留；不能把已折算数字再次乘底分。保存后更正权限待确认。

## 10. 打对家个人快捷记分板

四人，创建前确认底分，标题下显示房间信息和底分。上方四名入局玩家累计；左侧仅＋/−，加宽并铺满分配列；右侧仅两种数值，对应抓一个1倍、抓两个2倍。底分5主数字为5/10。

- 点击正负与分值后确认，只保存本人流水，不选择两名赢家，不联动其他三人，不维护搭档或牌局过程。
- 无明A、独立计算预览、分值下面倍率说明或最底部倍数规则栏。是否保留不含倍率的“抓一个/抓两个”短标签待P12确认，旧“抓一个·1倍/抓两个·2倍”不能当最新要求。
- 保存中禁用重复提交，失败保留选择，成功清空所选倍数、底分保留；不要求单次个人流水零和。

## 11. 记录与累计

### 11.1 记录页

- 默认筛选当前玩法，可切换其他玩法；按保存时间倒序。
- 九球展示单次操作：“我 · 大金 +20分 · 20:15”；详情显示操作人、时间与对应计分变动。
- 杀球展示全体完整结果；扑克展示本人或成员的独立流水及其底分/基础键，不把多人流水伪装成一次联动结算。
- 打分历史每条按自己的2人/3人名单显示基准60/40及净分；混合历史不随当前人数重算。可查看归属及修改过程，过程不重复累计。
- 没有记录时显示“还没有记录，记分后会显示在这里”，提供回到记分入口。
- 撤销、删除、更正按钮暂不作为已确认交付；P05确定后补充权限、确认文案、冲正后累计与审计展示。

### 11.2 累计页

- 先选玩法，再展示个人累计；标题明确“本房间 · 杀球累计”等上下文。
- 固定成员顺序展示，避免成绩每次变化时卡片跳位；不增加排行榜或排名动画。
- 正数带“+”，负数带“−”，0显示“0”；每个数附“分”或“颗”。
- 玩法无记录时展示空态，不能将另一玩法的累计带入。
- 成员以后离开仍应在旧记录中可辨识；退出房间及历史成员显示细节待P06/P07确定。

## 12. 通用状态与反馈

| 状态 | 界面反馈 | 行为 |
| --- | --- | --- |
| 初次加载 | 内容区骨架或加载提示 | 不展示伪造的0分为已读取结果 |
| 保存中 | 对应按钮加载，保留输入 | 防止同一次提交重复发出 |

| 已恢复连接 | 读取最新结果后消除提示 | 不将旧输入自动提交成新记录 |
| 牌归属冲突 | 指明号码及最新归属 | 更新该牌，允许继续选其他牌 |
| 底分或参与者上下文改变 | “计分设置已更新，请重新确认” | 保留可核对输入，不按新设置静默保存旧预览 |

Toast用于成功等短消息；失败、差额、离线等需要持续处理的状态使用页面内提示，不能一闪而过。

## 13. 视觉与可用性规范（设计提案）

### 13.1 方向

采用已选V4深色石墨绿工具界面，米白牌面及折算按钮；背景#10191C，面板#1C282C，正文#F4F5F1，次字#B2BFBD，主操作#367D65，强调#96DFBE。早期浅色方案只作历史参考，不再作为当前实现依据。

正负分通过符号、文字和颜色共同区分；例如正分深绿、负分深红，但不依赖颜色识别。差额使用提示色，不在正常等待他人记分时表现为严重报错。

### 13.2 尺寸和布局

- 以375逻辑像素宽手机为基准，覆盖320—430宽度；先单列自适应，不固定整页高度。
- 页面水平边距16，卡片内边距16，主要区块间距16—24；数字字段与姓名保持对齐。
- 累计主数字建议32—40，正文16，辅助说明14；使用支持数字等宽的字体表现减少跳动。
- 触控目标至少44×44逻辑像素，正负按钮有足够间距；15张牌不通过缩小触控区来强行塞入一屏。
- 长姓名截断但提供完整查看方式；“我”和分数不截断，负号不换行。
- 适配系统字体放大、刘海与底部安全区；输入时被编辑字段和预览结果可见，键盘不挡保存按钮。
- 微信分享使用原生能力；不设计自制联系人列表或自动发消息。
