# V4首页补充：最近房间

日期：2026-10-21。仅补充首页最近房间的静态设计与开发行为，不修改房间记分逻辑。

## 文件

`pages/default.svg`、`swipe.svg`、`pending.svg`、`failure.svg`、`empty.svg`分别为默认、左滑展开、删除中、失败、空态。

每张稿390×900逻辑px，延续V4颜色。高度为内容参考，不要求真机内容在一屏内，也不锁死页面高度。首页最近房间最多3条；业务配置若改2条，其余交互相同。

## 组件尺寸

- 页面水平边距16px（30.77rpx）；卡片宽为可用内容宽，390基准358px。
- 每条房间卡高120px（230.77rpx），卡间12px（23.08rpx），圆角12px。
- 右侧删除槽宽80px（153.85rpx），高同卡片，背景#913F48，白色文字；触控区不得小于44×44px。
- 删除槽在卡片右侧，由滑动显露。截图示意操作槽；实际移动前景层，不挤压或缩小原卡文字与按钮。
- 原卡层按横向位移−80px展开，0为收起；卡片容器裁切超出部分，圆角一致。禁止同时移动操作槽或让相邻卡片跟随。
- 最近房间标题18px/600；房间名17px/600；房间码、人数玩法、失败提示12px。保持深色底浅字。
- 创建和加入入口保持52px高、原V4色值不变。状态栏/胶囊仅占位，真实安全区由微信环境提供。

## 手势与状态规则

1. 普通态点击进入按钮正常入房；左滑不能触发入房。
2. 先识别方向，再移动卡片。建议移动超过8px且横向距离大于纵向1.5倍时锁定横向；否则保留纵向滚动。释放时超过删除槽一半（40px）展开，未达到则收起；阈值为开发建议，实际真机可调整。
3. 一次只展开一张。展开另一张先收起原张；右滑、点击外部或点击展开卡主体收起。点击用于收起时不得同时入房。
4. 点击删除立即进入提交中，禁用该条重复提交。此阶段保持条目，不能先显示永久删除成功。
5. 成功移除本人列表条目，从未删除条目按最近进入时间补足3条。提示“已从最近房间移除”。
6. 失败保持原条目，显示“移除失败，请重试”。保持可重新左滑或点击删除的可恢复状态，不导航、不清空成绩。
7. 全部移除后显示“暂无最近房间”，保留创建、加入入口，不暗示历史成绩已清除。
8. 删除状态需要持久化；刷新、重新打开、后台房间成绩更新都不能恢复该条。只有本人主动重新入房才恢复为最新条目。
9. 同一房间去重。列表展示上限不能等于数据永久保存上限，否则无法在删除后正确补位。

## 数据语义与权限

删除的是“当前用户—最近房间”的关联/可见状态，使用recent-entry remove/dismiss语义。不能调用解散房间、退出房间、删成员或删计分记录的接口。只能移除本人的条目，不操作其他用户列表。采用隐藏标记还是删除最近关联由后端确定，但必须满足刷新不恢复与重入可恢复。

推荐卡片字段：roomId、name、joinCode、selectedMode、memberCount、lastEnteredAt。移除成功后重新求最近列表；更新房间内容时间不能替代lastEnteredAt排序。

## 本次边界

这是一份静态开发补充，不表示小程序已实现手势、后端移除或真机验证。原首页图片及旧原型不包含这些状态，以本说明与新稿为准。对应PRD验收项HR01—HR06。
