## 交付内容与打开方式

- `index.html`：主页、杀球、打分三屏HTML，可点击的本地设计示例。
- `styles.css`：可检查的实际布局和组件样式。
- `prototype.js`：本地状态演示，不是生产业务实现，不调用现有接口。
- `tokens.json`：前端可提取的颜色、间距、字号和布局变量。
- `assets/card-01.svg`至`card-15.svg`：独立矢量号码牌，1=A、11=J、12=Q、13=K，14红Joker、15黑Joker；号码始终明确。
- `states.html`：组件及异常状态静态规格，供前端验收。

直接打开index.html即可使用，无外部CDN、字体下载或构建依赖。也可从仓库根目录运行 `python3 -m http.server 8765 --bind 127.0.0.1`，访问 `/docs/design/v4-handoff/`。

桌面展示三屏对照。窄屏显示单页，可用 `?screen=home`、`?screen=kill`、`?screen=score`。默认示例随刷新重置。按钮仅演示流程；创建房间、分享、访问真实历史都未实现。

## V4视觉还原与必要校正

保留石墨绿背景、墨绿主按钮、薄荷强调、米白扑克牌和克制边框。没有霓虹、光圈和立体台球。主页保留创建、加入、最近房间及玩法入口；杀球保留自己的牌、他人剩余数、撤销和末尾＋；打分保留三家分数及中央15张牌。

V4原图的5号牌角错误、Joker缺少明显号码和部分装饰性倒字不作为开发依据；以本包SVG及HTML为准。原图中的不明确图标简化为可实现符号，正式实现可按同一尺寸替换为项目图标，不依赖emoji或平台差异较大的字符画。

## 尺寸与适配

所有设计尺寸均为CSS逻辑px。390为基准宽，内容左右16，内部宽358。320—430宽自适应，不整体缩放画布，不锁死页面高度。

| 元素 | 尺寸/规则 |
| --- | --- |
| 系统和导航占位 | 36 + 52；仅HTML示意，真机读取微信导航/安全区信息 |
| 页面主标题 | 22 / 半粗；主页品牌32 |
| 正文/控件/辅助文字 | 14 / 16 / 12 |
| 主按钮 | 高至少52、圆角12、宽100% |
| 触控目标 | 至少44×44，包括撤销与弹窗关闭 |
| 面板 | 圆角12、边框1、内边距12或16 |
| 标签导航 | 高52、激活下划线3 |
| 自己的牌 | 三列；列距12；390基准单牌约111×144 |
| 撤销 | 已进牌上方独立44高触控区；每行预留48间隔避免遮挡上一行 |
| 公共牌 | 三列五行；列/行距8；390基准单牌约114×60 |
| 个人分数 | 28、等宽数字、明确分单位 |
| 加号空白牌 | 与自己牌等高、虚线边框、中间＋、文字说明 |
| 弹窗 | 底部面板，顶角20、最大85%视口、内部可滚动 |

牌尺寸计算：`(可用内容宽 - 两个列间距) / 3`。小屏、长姓名、大字体允许纵向滚动；不可压缩触控区域以强行保持一屏。已进标签不换行。已进仍保留号码并弱化，不隐藏整张牌。

Taro/微信适配时，若使用750设计rpx体系，`rpx = 本稿px × 750 / 390`；不要把390稿的16px机械当成32rpx。文本与命中区域分别检查。原生胶囊不能用本稿模拟胶囊代替，也不能点击模拟胶囊。

## 页面组件和事件契约

### 首页

`HomeHero`、`RoomEntryActions`、`RecentRoomCard`、`ModeEntry`。

- 创建：生产环境发起创建请求，成功后进入房间，不在成功前展示虚构房间码。
- 加入：输入、校验、查询房间、加入确认；本原型仅示例码628391。
- 最近房间：恢复身份和状态，不生成新房间。
- 其他玩法入口：本包不扩展为九球或扑克设计。

### 杀球

`OpponentCount`、`HandCard`、`UndoControl`、`PenaltyAddCard`、`TransferPicker`、`KillResultSheet`。

推荐渲染数据：`ballId, ownerId, potted, revision`。`initialOwnerId`与当前归属分开保存，不应被转归覆盖。双方剩余数来自当前归属下未进球数。

| 事件 | 行为与反馈 |
| --- | --- |
| 点击本人未进牌 | 请求标记已进；成功后减1、显示撤销；失败保持原状态 |
| 点击本人已进牌面 | 不重复扣数；撤销必须使用上方按钮 |
| 点击撤销 | 请求恢复未进；成功加1；按钮提交中禁用 |
| 点击＋ | 弹窗选择1—15中非本人当前持有的牌；自己的牌禁选 |
| 确认转入 | 原主人移除、本人增加并恢复未进，一次事务生效；成功更新两人数值 |
| 取消弹窗 | 不改变牌及分数 |
| 保存最终结果 | 赢家正分=所有其他人剩余数之和；每人负分=-其剩余数 |

原主人未进球转入时：本人+1、原主人−1；原主人已进球转入时：本人+1、原主人剩余数不变。进球撤销不撤销转归。

已发牌/未发牌、发牌中、进球提交中、已进、撤销中、转入选中/禁选、请求失败、并发冲突、结果保存中/成功等状态必须可表达，静态参考见states.html。

本HTML初始已经发好示例牌。随机发牌按钮、新一轮、误转归回退等权限仍按PRD待确认项，不把此原型当作已完成随机分配业务。

### 打分

`PlayerScore`、`Progress`、`PublicCard`、`OwnershipSheet`、`CompleteResultAction`。

- 未分配牌点击直接请求归本人，数字累加对应球号；不弹选择得分人。
- 已分配牌显示归属文字，并用淡绿/淡蓝辅助区分；不能仅凭颜色。
- 点已分配牌可退回或改归属；保存原操作者和修改者，显示修改人。
- 同一牌冲突以服务器结果为准，失败提示最新归属，不覆盖。
- 15张未全部分配，保存完整结果按钮禁用，并显示剩余张数。
- 完整结果为每人进球分减40，主动保存一次；完成后禁止重复保存。
- 已结算后的更正策略尚待确认，原型明确提示，不直接修改累计。

## 保存与同步的生产约束

本原型为了让设计师即时检查状态采用本地同步更新；正式前端必须有pending/failed/conflict状态，不能将这个本地行为直接当作成功保存。mutation使用唯一请求标识，重试同请求去重；保存全体结果为一次完整操作。订阅只监听当前房间，离开取消。断网不承诺离线合并。

房间记录与累计在本原型只汇总当前页面保存的示例数据，不影响仓库业务数据。所有成员身份、显示名、分配与服务器权限由真实接口提供。

- 三屏能独立查看，关键布局与V4一致。
- 15号牌含明确数字15，14号含14，1—15无重复遗漏，牌角对应正确。

- 记录、累计及原生操作边界明确；不把本地演示作为后端完成。
